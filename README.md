# Мини-CRM

Очередь заявок с публичного виджета и рабочий стол сотрудника. Клиент оставляет имя, телефон, почту и текст, потом смотрит статус и ответ по номеру заявки и телефону. Сотрудник берёт заявку, ставит приоритет, срок, метку и внутреннюю заметку.

Рабочий стол собран по плотной тройке из `design-demos`: рельс, очередь и карточка. Черновики лежат рядом: `01-cinematic`, `02-linear`, `03-supernormal`.

## Стек

- Next.js 16, React 19, TypeScript
- Drizzle ORM и SQLite (`data/crm.sqlite`)
- Better Auth, вход по почте и паролю, роли администратор и менеджер
- Zod для полей виджета
- Motion для палитры команд и листа заявки на узком экране

Регистрации нет. Оба сотрудника заведены сидом.

## Запуск

Нужны Node.js 22 и [just](https://just.systems). Без just те же команды запускаются через npm.

```bash
just dev
just test
just check
just seed
```

`just dev` поднимает сервер на порту 3000. Другой порт ломает вход: origin не совпадёт с `BETTER_AUTH_URL`. `just check` гоняет проверку типов, тесты и lint. `just seed` каждый раз собирает базу заново.

Те же шаги без just:

```bash
npm install
npm test
npm run seed
npm run dev
```

`node_modules` в этой копии уже собран. Повторный `npm install` на диске Windows из WSL иногда падает на `better-sqlite3`: у `node-gyp` нет права на запуск. Пока модуль на месте, ставить заново не нужно.

Приложение открывается на http://localhost:3000.

Вход:

- `admin@example.com` / `password` — Анна Соколова, администратор
- `manager@example.com` / `password` — Илья Морозов, менеджер

В сиде пять исходных клиентов (`+79990000001` … `+79990000005`, `client1@example.com` …) и ещё пять с компаниями. Заявки разложены по сегодня, неделе, месяцу и более ранним датам, с разными статусами, приоритетами и исполнителями. Это демо-данные, не журнал реального клиента.

Локально, если `BETTER_AUTH_SECRET` пустой или короче 32 символов, подставляется секрет для демо. В production без своего секрета приложение не стартует. Пример переменных — в `.env.example`. Пароли сида на странице входа оставлены нарочно: это локальное демо.

## Что умеет стол

- Очередь с поиском по теме, клиенту, телефону и почте
- Фильтры: мои, свободные, просрочка, статус, приоритет, даты
- Карточка клиента и история его заявок. Сотрудник правит имя, компанию, телефон и почту. Виджет уже сохранённую карточку не меняет
- Приоритет и срок от момента заявки: срочно 4 часа, высокий 24 часа, обычный 72 часа, низкий 7 суток. Смена приоритета пересчитывает срок
- «Взять себе»: назначает вас и переводит новую заявку в работу
- Внутренние заметки и отдельный ответ клиенту. Ответ в карточке, на почту не уходит и сам статус не меняет. История: статус, приоритет, исполнитель, метка, ответ
- Палитра `Ctrl+K`
- Сводка считает живые числа: сегодня, неделя с понедельника, месяц, статусы, свободные, просроченные, нагрузка. Процентов «роста» нет
- Виджет: `POST /api/tickets`. Одна заявка в календарные сутки по Москве на телефон или почту. Если телефон и почта не сходятся с карточкой, ответ один и тот же, без подсказки, какое поле уже есть. До пяти файлов, каждый не больше 10 МБ. Не принимаются страницы и исполняемые типы: html, svg, js, exe и соседние
- Статус заявки: `/status`. Клиент вводит номер и телефон. Совпали — видит номер, тему, статус и текст ответа. Не совпали — одна фраза и для чужого номера, и для чужого телефона. Заметки, исполнитель, метки и файлы на страницу не попадают. 30 попыток с адреса и 20 на один номер за 15 минут
- Вход: 8 неудачных попыток на почту и 30 на адрес за 15 минут. Успешный вход снимает счётчик почты. Виджет: 10 заявок в час с одного адреса и 40 в час на всех. Адрес из заголовка можно подделать, поэтому общий потолок важнее
- Файлы и сводку `GET /api/tickets/statistics` видит только сотрудник. Назначить заявку можно только администратору или менеджеру

Первый перевод в «Обработан» записывает время ответа и больше его не меняет.

Календарные сутки, неделя и месяц считаются по Москве.
